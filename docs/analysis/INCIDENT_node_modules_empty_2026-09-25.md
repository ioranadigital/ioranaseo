# Incidencia técnica: node_modules se vacía inesperadamente durante el desarrollo

**Fecha:** 2026-09-25 | **Estado:** ABIERTA, sin investigar | **Ámbito:** independiente del trabajo de UI (Home / Presencia journey)

## Síntoma
Durante la sesión de trabajo en `ioranaseo`, los directorios de paquetes dentro de
`node_modules/.pnpm/*/node_modules/<pkg>` (empezando por `next`, luego `styled-jsx`, `next/dist/pages`, etc.)
aparecieron vacíos. Errores observados:

- `Cannot find module '...\node_modules\next\dist\bin\next'`
- `Cannot find module './impl'`
- `Cannot find module 'styled-jsx/package.json'`
- `Cannot find module 'next/dist/pages/_app'` (al arrancar `next dev`)

## Observaciones (sin causa verificada)
- Ocurrió al menos 5 veces en una sesión, varias veces justo después de un `pnpm build` correcto o tras
  `pnpm install --frozen-lockfile --force`.
- `pnpm install --frozen-lockfile` sin `--force` respondía "Already up to date" pese a los directorios vacíos.
- `pnpm install --frozen-lockfile --force` restauraba todo (~10 s); `package.json` y `pnpm-lock.yaml` no cambiaron.
- No había procesos node/pnpm activos ni detecciones de Windows Defender (`Get-MpThreatDetection` vacío) en el momento de comprobarlo.
- No se investigó más (fuera de alcance).

## Workaround usado
`pnpm install --frozen-lockfile --force` dentro de `E:\git\interno\ioranaseo`, verificar que
`node_modules/next/dist/pages` existe, y arrancar `pnpm dev`.

Investigar como incidencia separada (antivirus/sincronización de carpetas, otro proceso que limpie, almacén pnpm en otra unidad, etc.).
