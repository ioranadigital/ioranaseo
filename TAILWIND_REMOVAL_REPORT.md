## SUMMARY

Tailwind CSS has been completely removed from IORANA SEO 2.0. The 7 inert
utility usages identified in the audit were replaced with explicit CSS
(scoped `<style>` blocks + `@media` queries, the same pattern already
validated in the Hero.tsx and LandingsHeader.tsx fixes), the `@tailwind`
directives were removed from `globals.css`, and the `tailwindcss` /
`@tailwindcss/postcss` packages were uninstalled via `pnpm remove`.

No `postcss.config` or `tailwind.config` existed before or after — nothing to
delete there.

## 2. CSS REPLACEMENT PATTERN

Each replacement follows the same shape already validated in this codebase:

```css
.{component}-connector-{line|arrow} {
  display: none;
}

@media (min-width: 1024px) {
  .{component}-connector-line {
    display: block;   /* or flex, matching the element's original layout role */
  }
}
```

Declared inside each component's existing inline `<style>` block — no new
files, no global stylesheet changes, no new breakpoints (the project's
existing 375/430/768/1024/1280/1440 set is unchanged).

**Geometry preserved exactly.** Only the `className` attribute changed on
each element; every inline `style={}` property (position, top/left/right,
width/height, color, opacity, z-index) is untouched — desktop appearance at
1024/1280/1440 is byte-for-byte the same positioning as before, just now
actually gated by real CSS instead of an inert utility class.

## 3. WHY `min-width: 1024px` FOR ALL THREE (INCLUDING PROCESSSTEPS)

`NuestroSistema.tsx` and `OurMethod.tsx` originally used Tailwind's `lg:`
(1024px) breakpoint — straightforward 1:1 mapping to explicit CSS.

`ProcessSteps.tsx` originally used `md:` (768px). Per this task's explicit
instruction (§2: "Normalizar comportamiento: <1024px HIDDEN, >=1024px
VISIBLE" and §12: expected result table listing 768px → hidden for all three
components, 1280px → visible for all three), all three were normalized to
the same 1024px cutoff rather than preserving ProcessSteps' original 768px
one.

**One side effect worth flagging explicitly:** `ProcessSteps.tsx` already has
its own mobile-specific CSS (`@media (max-width: 768px)`) that switches the
step layout to a vertical stack and draws its own vertical connector via a
`::before` pseudo-element. With the horizontal connector now gated at
`min-width: 1024px` instead of `min-width: 768px`, there's a band between
769px and 1023px where the layout is horizontal (the `max-width: 768px` stack
rule no longer applies) but the horizontal connector is hidden (the new
`min-width: 1024px` rule hasn't kicked in yet) — a small visual gap in that
range that didn't exist under the original `md:` breakpoint. This is a
direct, explicit consequence of the requested normalization, not an
oversight; flagging it here in case it's visible on review and needs a
follow-up decision (keep normalized at 1024px, or give ProcessSteps its own
768px cutoff to eliminate the gap).

**Also worth flagging: `ProcessSteps.tsx` is not currently rendered
anywhere.** It is not imported by `/web-para-empresas/page.tsx` (which uses
Hero, VisibilityToResults, OurMethod, WhatIncludes, Pricing, FAQForm — no
ProcessSteps) or by any other page in the active project. The fix applied to
it is mechanically correct and ready if the component is ever wired up, but
has zero visible effect today because the component isn't in any render
tree. This was true before this change as well — not a regression introduced
here.
